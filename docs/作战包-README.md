# 题衡 PaperCompile · 参赛作战包

> **先定蓝图，再出好题。**
> 面向高校教师的 AI 命题编译器：把一份教学大纲，编译成一份可解释、可审查、可复现的试卷。

---

## 这份作战包是什么

这不是一堆“比赛建议”，而是一套可以直接执行的参赛作战包。它已经替你完成了三件最耗时、最容易走偏的事：

1. **选定了一个简单、实用、能拿分的项目主题**，并完成了产品定位与差异化设计。
2. **把比赛规则拆成了评分策略和证据清单**，你知道每一步为什么做、做完要留下什么。
3. **把开发过程拆成了 7 天、按功能切好的提示词**，你可以直接复制给 AI 编码搭档，一次只推进一个模块。

> 当前仓库里只有方案与提示词，还没有代码。这是故意的：先对齐，再开工。下一条提示词 `P01` 才会初始化工程。

### 它不是什么

- 不是“给 ChatGPT 套一个输入框”的套壳出题器。
- 不是题库、刷题软件、自动阅卷系统。
- 不是大而全的教务平台。
- 不替代教师做最终判断；它把教师从重复劳动里解放出来，把终审权留给教师。

## 为什么是这个题

比赛有 10 个方向，最容易拿高分的不一定是特效最炫的，而是**真实痛点 + 完整闭环 + 可验证过程**三者都占的。

| 选择标准 | 题衡的答案 |
|---|---|
| 真问题 | 教师每学期都要出卷，时间成本高，覆盖与难度难证明 |
| 能闭环 | 输入大纲 → 配置蓝图 → 生成 → 审校 → 成卷 → 导出，一条线跑通 |
| 能演示 | 5 分钟内能看到“大纲变试卷”，视觉变化强 |
| 能控风险 | 核心分配与组卷是确定性代码；AI 失败时有演示模式兜底 |
| 有创新 | 不是让 AI 自由发挥，而是用“命题契约”约束 AI，再让另一个 Agent 独立审题 |
| 工程可讲 | 有算法、有 schema、有状态机、有测试、有安全边界，不是纯 UI |
| 可复现 | Prompt 版本、模型参数、种子、快照哈希、回放包，全链路留痕 |

相比之下，“多 Agent 聊天看板”容易同质化，“3D 数字孪生”视觉强但交付风险高，“校园二手交易”很难证明不是玩具。题衡是一个**小而深**的切口。

## 核心闭环

```text
教学大纲
   │  Agent 1：大纲解析（只抽取，不发明；每条知识点带原文出处）
   ▼
知识点图谱（教师可增删改）
   │  教师配置：总分 / 时长 / 题型 / 章节权重 / 难度比例
   ▼
命题蓝图（系统校验 + 确定性分配 + 覆盖矩阵）
   │  每个题目槽位生成一份“命题契约”
   ▼
Agent 2：命题官（按契约出题）
   │
Agent 3：审题官（先独立作答，再比对答案，输出证据化问题）
   │  有问题 → 定向修复 → 复审（最多 2 轮）
   ▼
教师审校台（编辑 / 锁定 / 单题重生成 / 通过）
   │  确定性编译器组卷
   ▼
A4 试卷 + 答案卷 + 质量报告 + 复现包
```

**3 个 AI 角色 + 1 个确定性编译器。** 不吹“十几个 Agent”，但每一个角色都有明确的输入、输出、校验和失败处理。

## 评分策略一眼看懂

| 评分维度 | 权重 | 我们的打法 | 要留下的证据 |
|---|---:|---|---|
| 过程可复现与演进链路 | 25% | 小步提交、Prompt 日志、快照回放、10 分钟复现指南 | 40+ 条真实 commit、3 条完整 Prompt 链、测试记录 |
| 解题有效性与实用价值 | 25% | 真实教师访谈、真实课程大纲、前后耗时对比 | 访谈纪要、试用反馈、任务完成记录 |
| 方法创新性与意图控制 | 20% | 蓝图先行、命题契约、独立审题、证据化修复 | 架构图、契约 schema、Prompt 设计说明 |
| 工程质量与架构设计 | 15% | TypeScript + Zod + 确定性算法 + 测试 + 安全边界 | 测试报告、CI、无高危漏洞、错误处理 |
| 用户体验与产品精细度 | 15% | 编辑部风格视觉、流式状态、空/错/加载态、打印体验 | 截图、录屏、可用性测试记录 |

> 目标不是“功能最多”，而是**每个评分项都有硬证据**。评委会问的不是“你做了什么”，而是“我凭什么相信这是真的、是你做的、能复现”。

## 现在就从这三步开始

### 第 1 步：花 10 分钟确认方向

读 `docs/00-作战地图.md`。只确认三件事：

- 这个项目你愿意讲 7 天，不反感。
- 你认可“深度优先、演示模式兜底、证据链优先”的打法。
- 你接受 P0 范围，不偷偷加登录、社区、支付、题库。

### 第 2 步：把比赛环境准备好

- 安装 Node.js 20+（当前机器是 v24，可直接用）与 Git。
- 注册/登录 GitHub 或 Gitee，新建一个 **Public** 仓库，先不要勾选任何模板。
- 设置 Git 身份（不要用别人的身份，也不要伪造提交时间）：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

- 准备一个屏幕录制工具（Windows 自带 Xbox Game Bar 即可），从第一次 AI 协作就开录。
- 如果你能联系到 2–3 位真实教师/助教，现在就发出试用邀请；这是 25% 实用价值分的关键证据。

### 第 3 步：粘贴第一条提示词

打开 `docs/05-提示词库.md`，先复制 **P00**，再复制 **P01**。不要一次粘贴十条。每完成一个功能，运行检查、手动验收、提交、更新 `CURRENT_STATE.md`，再进入下一条。

## 三条铁律

1. **不伪造证据。** 没有真实用户访谈，就写“尚未验证”，不要编数据；评委会追问，也可能要求现场复现。
2. **不一次性提交。** 每个功能模块、每次核心 AI 对话，至少对应一次有意义的提交。禁止最后一天把整个项目塞进一个 `initial commit`。
3. **不牺牲闭环换功能。** 先让“大纲 → 试卷”这条主线稳定可演示，再考虑动画、导出格式、多课程。功能冻结日后只修 bug 和打磨。
