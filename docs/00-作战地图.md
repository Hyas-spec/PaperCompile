# 00 · 作战地图（一页纸）

> 这一页只回答四个问题：做什么、凭什么赢、怎么排期、今天干什么。

## 1. 我们做什么

**题衡 PaperCompile**：把教学大纲“编译”成一份可解释、可审查、可复现的试卷。

```text
大纲 → 知识点 → 命题蓝图 → 命题契约 → AI 出题/审题 → 教师终审 → 成卷
```

- 参赛方向：**04 低代码与智能表单生成引擎**，融合 **01 多 Agent 协同**。
- 演示场景：《数据结构》期中考试，100 分 / 120 分钟。
- 核心用户：高校青年教师、课程组、助教。
- 一句话价值：**把 4–8 小时的出卷，压缩到 30 分钟，并且每一步都有依据。**

## 2. 凭什么赢

评委会在很短时间里判断三件事：**是不是真问题、是不是你做的、能不能复现。** 我们的打法是：

| 评委的疑问 | 我们的回答 | 留下的证据 |
|---|---|---|
| 这是真需求吗？ | 教师每学期都要出卷；时间花在覆盖、难度、答案、排版上 | 2–3 位教师的访谈 + 试用记录 + 前后耗时 |
| 这不就是 ChatGPT 套壳？ | 蓝图先行 + 命题契约 + 独立审题 + 确定性组卷；AI 不能自由改结构 | 架构图、契约 schema、审题证据、修复 diff |
| AI 说的能信吗？ | 审题官先独立作答再比对；问题必须引用证据；教师终审 | 风险列表、修复前后对比、质量报告 |
| 没有 Key 能演示吗？ | 内置演示模式，离线跑通全流程；真实模式可选 | 现场演示 + 录屏兜底 |
| 过程是真的吗？ | 每天小步提交；每次核心对话有 Prompt 日志；代码可回放 | 40+ commits、3 条完整 Prompt 链、快照回放 |
| 工程靠谱吗？ | 确定性算法、Zod、单测、E2E、超时/重试/中断、无高危漏洞 | CI 报告、测试截图、代码结构 |

### 三个记忆点（答辩时反复说）

1. **不是让 AI 写一张卷，而是先编译出一张卷的“施工图”。**
2. **不是让 AI 自己检查自己，而是让另一个 Agent 先独立做一遍。**
3. **不是“生成完就结束”，而是把整张卷连同证据打包，随时可以回放。**

## 3. 评分目标与优先级

| 维度 | 权重 | 目标 | 第一优先级动作 |
|---|---:|---|---|
| 过程可复现与演进链路 | 25% | 24–25 | 从第一天开始小步提交 + Prompt 日志 + 快照 |
| 解题有效性与实用价值 | 25% | 21–23 | 真实教师访谈 + 真实大纲 + 前后耗时 |
| 方法创新性与意图控制 | 20% | 17–18 | 蓝图/契约/独立审题讲清楚，并有代码支撑 |
| 工程质量与架构设计 | 15% | 13–14 | 确定性算法 + schema + 测试 + 错误处理 |
| 用户体验与产品精细度 | 15% | 13–14 | 编辑部视觉 + 流式状态 + 打印体验 |

> 不追求满分。**任何一项低于 60% 都会拖垮总分**，所以先补短板，再把长板讲透。

## 4. 7 天排期

| 天 | 目标 | 关门条件（做不到就不进入下一天） |
|---|---|---|
| D1 | 工程骨架 + 设计系统 + 五步导航 | `npm run dev` 能打开；`npm run check` 通过；首条 commit |
| D2 | 大纲/知识点 + 蓝图 + 分配算法 | 100 分示例卷分配正确；边界单测通过 |
| D3 | AI 网关 + 演示模式 + 大纲解析 | 无 Key 也能解析；断网/报错可恢复 |
| D4 | 命题 + 审题 + 修复 + 基础审校 | 10 道题全有契约、答案、审题结果 |
| D5 | 组卷 + A4 预览 + 快照/复现包 | 打印总分正确；快照可导入回放 |
| D6 | 完整审校体验 + 响应式 + 安全 + E2E | 主线 E2E 通过；无 P0 阻断 bug |
| D7 | 文档 + 视频 + 全新克隆验收 | 陌生人 10 分钟能跑起来；材料齐全 |

> 每天只有 2–3 小时：把 7 天拉成 12–14 天，顺序不变。
> 只剩 72 小时：看 `04-7天执行手册.md` 的压缩版，砍掉 P1，只保主线。

## 5. 演示叙事（5 分钟版）

| 时间 | 画面 | 台词核心 |
|---|---|---|
| 0:00 | 一份杂乱大纲 vs 一份成卷，计时器 4 小时 → 22 分钟 | “出卷最痛的从来不是写题，是让题对得上大纲。” |
| 0:30 | 粘贴大纲，解析出章节/知识点 | “AI 只做抽取，每条知识点必须带原文出处。” |
| 1:00 | 调蓝图：树/图权重提高，难度 3:5:2 | “结构由教师定，AI 不能自由发挥。” |
| 1:40 | 生成，Agent 工作台流式显示 | “命题官按契约出题，审题官先独立做一遍。” |
| 2:40 | 一道题被标红，查看证据，定向修复 | “不是重写整张卷，只修被指出的问题。” |
| 3:30 | 成卷预览、答案卷、质量报告 | “总分、覆盖、难度，全部可核对。” |
| 4:10 | 导出复现包，回放 | “同一份快照，随时可以还原今天的现场。” |
| 4:40 | 架构/提交记录/用户反馈 | “不是 Demo，是一条可复现的工程链路。” |

完整 5–8 分钟脚本见 `06-提交材料与视频脚本.md`。

## 6. 今天只做三件事

1. **读**：本文件 + `01-比赛规则拆解与评分策略.md` 的“硬性提交清单”。
2. **定**：确认主题；把仓库、Git 身份、录屏工具准备好；给 2 位教师发试用邀请。
3. **开**：粘贴 `05-提示词库.md` 的 **P00**，再粘贴 **P01**；今天结束前完成第一条 commit。

## 7. 三条失败线（碰到就停）

- **功能蔓延**：开始做登录、社区、题库、自动阅卷 → 立刻砍。
- **演示靠现场 AI**：没有演示模式兜底，网络/接口一挂就全挂 → D3 必须解决。
- **最后一天才写文档/做视频**：D5 开始写，D7 只做收尾 → 否则必然延期。

## 8. 一句话收束

> 我们不是在做一个“会出题的聊天框”，而是在做一台**可以被检查、被信任、被复现的命题机器**。
