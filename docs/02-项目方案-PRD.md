# 02 · 项目方案 PRD

> 产品名：**题衡 PaperCompile**
> 副标题：**先定蓝图，再出好题。**
> 版本：v1.0（比赛版）
> 参赛方向：04 低代码与智能表单生成引擎（融合 01 多 Agent 协同）

---

## 1. 项目定位

### 1.1 一句话

把一份教学大纲，编译成一份**可解释、可审查、可复现**的试卷。

### 1.2 产品形态

一个本地优先的 Web 工作台。教师在一个界面里完成：

```text
载入大纲 → 确认知识点 → 配置蓝图 → 生成题目 → 审校 → 成卷 → 导出/回放
```

### 1.3 不是什么

- 不是题库，不提供“海量现成题”。
- 不是自动阅卷，不做学生端。
- 不是通用文档生成器，不接论文/公文/营销文案。
- 不是“一键出卷、教师闭眼用”；它是教师的**副驾**，不是替代者。
- 不承诺 AI 生成的题 100% 正确；它承诺的是**可检查、可修复、可追溯**。

## 2. 用户与场景

### 2.1 主要用户

**高校青年教师 / 课程组 / 助教**

- 每学期 1–3 门课，需要期中/期末/随堂测验。
- 有教学大纲和教材，但没有现成题库，或题库与自己的教学重点不匹配。
- 出卷时间通常挤在晚上/周末，重复劳动多。
- 对 AI 有兴趣，但不敢直接把 ChatGPT 生成的卷子发给学生。

### 2.2 次要用户

- 企业培训认证出题人：需要按能力模型组卷。
- 竞赛/夏令营命题人：需要按知识点和难度快速出题。

### 2.3 核心场景

**场景 A：期中考试（主演示）**

- 课程：《数据结构》
- 100 分，120 分钟，6 章，单选/填空/简答（综合应用按简答承载）
- 教师希望：覆盖 6 章、难度 3:5:2、答案准确、排版可直接打印

**场景 B：随堂小测**

- 20 分，15 分钟，2 章，只有单选 + 填空
- 教师希望：5 分钟内组一套，能导出 PDF

**场景 C：补考/备用卷**

- 同一蓝图，换一套题；结构、难度、覆盖保持一致
- 教师希望：不要与正考卷重复，能对比两套卷的覆盖

> MVP 只把场景 A 做深；B/C 作为同一套能力的自然延伸，不额外做入口。

## 3. 痛点与现有方案

### 3.1 痛点拆解

| 环节 | 教师的真实动作 | 痛点 |
|---|---|---|
| 对大纲 | 翻教学大纲/教材目录，回忆哪些讲过 | 知识点散落在文档里，容易漏章 |
| 配结构 | 算每题分值、题型比例、难度 | 心算易错；改一个分值要全盘重算 |
| 找题/改题 | 翻题库、改旧题、自己编 | 题库不匹配；旧题重复；改题耗时 |
| 做答案 | 自己写答案、评分点 | 容易漏步骤；综合题评分点难统一 |
| 审题 | 自己从头做一遍 | 时间不够；看不出歧义 |
| 排版 | Word 调格式、编题号、做答案卷 | 机械劳动；打印容易截断 |

### 3.2 现有替代方案

| 方案 | 优点 | 不足 |
|---|---|---|
| 手工出卷 | 可控、符合教学习惯 | 4–8 小时；重复劳动；难复用 |
| 学校题库 | 有现成题 | 与自己的大纲/重点不匹配；题型固定；陈旧 |
| 直接问 ChatGPT | 快 | 结构漂移、覆盖不可控、答案可能错、无法审查、不可复现 |
| 通用 AI 出题工具 | 有一些模板 | 多数是“输入主题→出一堆题”，没有蓝图、没有审题、没有组卷闭环 |

### 3.3 机会

教师不缺“生成文字”的工具，缺的是**能对结果负责的工作流**：

- 结构要能自己定；
- 每题要有依据；
- 答案要能被独立检查；
- 改题要能只改有问题的那一道；
- 成卷要能打印；
- 整个过程要能回放。

## 4. 价值主张与差异化

### 4.1 价值主张

> **30 分钟，从大纲到一份有依据、可打印的试卷。**

不是“更快地生成”，而是“更快地得到一个**敢用**的结果”。

### 4.2 三个差异化

#### 差异化一：Blueprint-first（蓝图先行）

传统 AI 出题：`主题 → 一大段 Prompt → 一堆题 → 人工挑`。

题衡：`大纲 → 知识点 → 蓝图（分值/章节/难度/题型）→ 契约 → 题目`。

蓝图是**确定性资产**：总分必须对、章节权重必须可解释、难度分布必须可核对。AI 不能改变结构，只能在契约里填内容。

#### 差异化二：命题契约（Contract-bound Generation）

每个题目槽位在生成前就有一份契约：

```json
{
  "contractId": "C-03",
  "chapter": "树与二叉树",
  "knowledgePointIds": ["KP-12", "KP-13"],
  "type": "short_answer",
  "points": 10,
  "difficulty": "medium",
  "bloom": "apply",
  "requirements": {
    "mustCover": ["二叉树的遍历", "递归"],
    "answerMustInclude": ["前序/中序/后序", "递归终止条件"],
    "forbidden": ["超出大纲的平衡树旋转"]
  }
}
```

生成后逐条校验；不合规的题不进审校台，直接打回或标记。

#### 差异化三：独立审题 + 证据化修复

审题 Agent **不看**命题 Agent 的“创作思路”，只拿题目 + 契约 + 评分点：

1. 先独立做一遍，写出自己的答案；
2. 再比对题目给出的答案；
3. 输出问题，必须引用具体题干/答案片段作为证据；
4. 命题 Agent 只修复被指出的问题；
5. 复审；两轮不过，交给人。

这不是“让 AI 自查”，而是**对抗式校验**。

### 4.3 与“直接问 ChatGPT”的对比

| 维度 | ChatGPT 直接出卷 | 题衡 |
|---|---|---|
| 结构控制 | 靠 Prompt 描述，容易漂 | 蓝图 + 契约，结构确定 |
| 覆盖证明 | 事后自己数 | 生成前分配，生成后矩阵核对 |
| 答案可信 | 靠模型自觉 | 独立作答 + 比对 + 证据 |
| 改题 | 重新生成一整段 | 单题定向修复，保留其余 |
| 排版 | 复制到 Word 手工调 | A4 预览 + 打印样式 |
| 复现 | 聊天记录，难还原 | 快照 + 哈希 + 回放包 |
| 教师控制 | 弱 | 三个确认闸门 + 终审 |

## 5. 核心用户旅程

### 5.1 首次使用（3 分钟）

1. 打开应用，看到一句话说明 + “载入《数据结构》示例”按钮。
2. 点击示例，自动填入课程信息和大纲。
3. 点击“解析大纲”，右侧出现 6 章、24+ 知识点，每条带原文出处。
4. 教师快速扫一遍，删掉一条不讲的，点“确认大纲”。
5. 进入蓝图页，系统已按示例填好 100 分/120 分钟/3:5:2；教师改一处章节权重，看到覆盖矩阵实时变化。
6. 点“生成试卷”，Agent 工作台开始跑。
7. 生成完成后，进入审校台，看到 10 道题、2 个待处理问题。
8. 处理完，点“成卷”，看到 A4 试卷；点“打印/导出”。
9. 点“保存快照”，得到复现包。

### 5.2 熟手使用（10 分钟）

1. 粘贴自己的大纲。
2. 解析、微调知识点。
3. 用“上次的蓝图”复制一份，改总分/章节权重。
4. 生成、审校、导出。

### 5.3 失败路径

- 大纲解析失败：显示原始错误 + “重试” + “手动录入”。
- 某一道题生成失败：其余题继续；该槽位显示“待重试”，不阻塞整卷。
- 审题两轮仍有 blocker：标记“需人工处理”，不允许直接成卷（可强制导出草稿，但带水印）。
- API 超时/断网：保留已完成结果；提示“已保存，可重试”；演示模式可继续。
- 导入旧版本快照：schema 迁移或明确提示“版本不兼容”，不静默丢数据。

## 7. 关键页面与交互

### 7.1 应用外壳

```text
┌──────────────────────────────────────────────────────────────┐
│ 题衡 PaperCompile     《数据结构》期中考试     演示模式 · 已保存 │
├──────────┬───────────────────────────────────┬───────────────┤
│ 01 大纲  │                                   │ 本次考试       │
│ 02 蓝图  │           当前步骤工作区            │ 100 分 / 120 分│
│ 03 命题  │                                   │ 6 章 / 10 题   │
│ 04 审校  │                                   │ 覆盖 92%       │
│ 05 成卷  │                                   │               │
│          │                                   │ 质量提示       │
├──────────┴───────────────────────────────────┴───────────────┤
│ Agent 工作台：● 审题官 正在核对第 5 题答案…        中断/重试  │
└──────────────────────────────────────────────────────────────┘
```

- 左侧步骤条：已完成/当前/未开始；可回退，但未保存时确认。
- 右侧上下文面板：随步骤变化（知识点统计/蓝图覆盖/审题风险/成卷质量）。
- 底部 Agent 工作台：可折叠；显示阶段、当前任务、流式文本摘要、错误。
- 顶部：项目名可编辑、保存状态、演示模式徽标、导出入口。

### 7.2 步骤 01：大纲

- 左：大纲文本域（等宽/舒适行高），支持粘贴、清空、载入示例。
- 右：解析结果（章节折叠面板 + 知识点列表）。
- 每个知识点：标题、简述、原文出处（可展开）、重要性（1–3）、编辑/删除。
- 顶部统计：章节数、知识点数、疑似重复、未归属。
- 解析中：骨架屏 + 具体阶段文案，不用全屏转圈。
- 解析失败：保留原文，显示错误码 + 重试 + 手动录入。
- 确认闸门：知识点 < 6 个或存在空章节时，提示但不强行阻止（允许用户补）。

### 7.3 步骤 02：蓝图

- 基本信息：考试名称、课程、时长、总分。
- 难度比例：易/中/难三个数字/滑块，实时显示总和；不等于 100% 时禁用生成。
- 章节权重：每章一个百分比；提供“按知识点数均分”“恢复上次”按钮；总和必须 100%。
- 题型结构：表格（题型、题量、每题分值、小计）；支持增删行；小计合计必须等于总分。
- 约束：自由文本（如“不得出现教材原题”“综合题必须含一道图算法”）。
- 右侧实时预览：
  - 总分/题量/预计时长；
  - 章节覆盖条形图；
  - 难度分布；
  - 校验消息（error/warning）。
- 底部： “生成命题契约” → 进入命题页；若存在 error，按钮禁用并定位第一个错误。

### 7.4 步骤 03：命题

- 顶部：进度（3/3 个部分完成）、已用时间、token（可选）。
- Agent 工作台：
  - 大纲解析师：已完成；
  - 命题官：正在生成“综合应用题”；
  - 审题官：等待中。
- 题目卡片逐步出现：题号、题型、分值、章节、状态（生成中/待审/审题中/通过/需修复/失败）。
- 单题失败不影响其他题；提供“重试此题”。
- 全部完成后： “进入审校台”按钮；若有失败，显示“还有 1 题未完成”。

### 7.5 步骤 04：审校

三栏：

```text
筛选/统计        题目列表                 题目详情
全部 10          01 单选 · 2分 · 通过      题干（可编辑）
阻断 1           02 填空 · 2分 · 待修复    选项/答案/解析
重要 2           03 简答 · 10分 · 通过     契约侧栏
建议 3           ...                       审题证据 / 修复建议
通过 6                                      [修复] [重生成] [通过] [锁定]
```

- 筛选项：全部、阻断、重要、建议、待处理、已通过、已锁定。
- 题目详情：
  - 题干（Markdown + KaTeX 渲染；编辑时切源码）；
  - 选项（单选）；
  - 答案、解析、评分点；
  - 契约：章节、知识点、难度、Bloom、要求；
  - 审题：独立答案、是否一致、问题列表、证据引用；
  - 操作：定向修复、单题重生成、通过、锁定、删除（需确认）。
- 修复时展示 diff（改前/改后），教师确认才落库。
- 锁定后禁止 AI 覆盖；再次生成需先解锁。
- 底部固定： “N 题待处理” + “生成试卷”（有 blocker 时二次确认/禁止）。

### 7.6 步骤 05：成卷

- 左侧：A4 预览（缩放 75%/100%/fit）；页码；卷头；大题说明；题号连续。
- 顶部开关：试卷 / 答案卷 / 两者。
- 右侧：质量报告卡（覆盖、难度、契约合规、审题状态、答案完整）。
- 操作：打印/导出 PDF、导出 Markdown、导出 JSON、保存快照、复制复现包。
- 打印样式：
  - `@page { size: A4; margin: 18mm 16mm; }`
  - 隐藏导航、按钮、侧栏、Agent 工作台；
  - 题目不跨页断裂（`break-inside: avoid`）；
  - 答案卷独立分页；
  - 页脚页码。
- 空态：还没有成卷 → “先完成审校”。

### 7.7 版本历史

- 时间线：每次生成/修复/成卷/手动保存生成快照。
- 每条：时间、触发动作、题目数、风险数、哈希前 8 位。
- 操作：查看、恢复、导出、复制。
- 恢复前确认“当前未保存修改会丢失”。

## 8. 数据模型（产品视角）

```text
Course 1─n Chapter 1─n KnowledgePoint
ExamProject 1─1 Syllabus
ExamProject 1─1 Blueprint 1─n Section 1─n QuestionContract
QuestionContract 1─1 Question 1─n ReviewIssue
ExamProject 1─n Question
ExamProject 1─n Snapshot 1─1 Paper
```

| 实体 | 关键字段 |
|---|---|
| Course | id, name, code, description |
| Chapter | id, title, order, summary |
| KnowledgePoint | id, chapterId, title, description, sourceQuote, importance |
| Syllabus | rawText, parsedAt, parserVersion, warnings |
| Blueprint | totalPoints, durationMin, difficultyRatio, chapterWeights, sections, constraints, seed |
| Section | id, title, type, count, pointsPerQuestion, instructions |
| QuestionContract | id, sectionId, chapterId, kpIds, type, points, difficulty, bloom, requirements |
| Question | id, contractId, stem, options, answer, explanation, rubric, status, revisions |
| ReviewIssue | id, questionId, severity, category, message, evidence, suggestion, resolved |
| Paper | sections, order, totalPoints, answerKeyIncluded, generatedAt |
| Snapshot | id, label, createdAt, dataHash, promptVersions, modelConfig, seed, payload |

> 完整 Zod schema 见 `03-技术方案与架构.md`。所有实体带 `schemaVersion`，导入时校验。

## 9. 命题蓝图规则

### 9.1 输入

- 总分 `T`（默认 100，范围 20–200）
- 时长 `D`（默认 120 分钟，范围 10–300）
- 题型 section 列表：每题分值 `p_i`、题量 `n_i`
- 章节权重 `w_c`（百分比，总和 100）
- 难度比例 `d_easy/d_medium/d_hard`（百分比，总和 100）
- 约束文本（可选）

### 9.2 硬校验

1. `Σ(n_i × p_i) = T`，否则报错，显示差额。
2. `Σw_c = 100`，否则报错；提供“自动归一”按钮，但必须用户确认。
3. `Σd = 100`，同上。
4. 每个 section 的 `n_i ≥ 1`，`p_i > 0`，且为整数。
5. 每个参与分配的章节至少有一个知识点；空章节提醒。
6. 题量不能小于章节数（否则无法覆盖），给出 warning，允许继续但显示未覆盖章节。

### 9.3 分配算法（确定性）

1. 用最大余数法把章节权重换算成目标分值 `target_c`。
2. 用最大余数法把难度比例换算成目标分值 `target_d`。
3. 生成所有题目槽位（section × count），按分值从大到小排序。
4. 每个槽位：选“剩余目标分值最大”的章节；再选“剩余目标分值最大”的难度。
5. 在该章节内用带种子的 PRNG 选知识点，优先未使用、importance 高；用尽后允许重复但标记。
6. 生成契约；计算实际分布与目标的偏差。
7. 校验：每个章节偏差 ≤ 单题最大分值；否则显示 warning 和具体章节。

> 不需要复杂的最优化求解器。最大余数 + 贪心足够，且更容易解释、测试、复现。

### 9.4 种子与复现

- 蓝图保存 `seed`（默认随机生成，可手动固定）。
- 同一 seed + 同一蓝图 → 同一套契约分配（题目内容是否相同取决于 AI 模式；演示模式完全一致）。
- 真实 AI 模式不承诺逐字相同；快照保存实际输出，回放不重新调用模型。

## 10. 多 Agent 流程

### 10.1 角色

| 角色 | 类型 | 输入 | 输出 | 失败处理 |
|---|---|---|---|---|
| 大纲解析师 | LLM | 大纲原文 | 章节/知识点/出处/警告 | 重试 1 次；仍失败转手动 |
| 命题官 | LLM | 契约 + 知识点 + 约束 | 题目/答案/解析/评分点 | 单题重试；不影响其他题 |
| 审题官 | LLM | 题目 + 契约（不含生成理由） | 独立答案/问题/证据/结论 | 重试 1 次；仍失败标记“未审” |
| 组卷编译器 | 确定性代码 | 已通过题目 + 蓝图 | 试卷/答案卷/质量报告 | 校验失败则阻止导出 |

### 10.2 三个确认闸门

1. **大纲闸门**：教师确认知识点后，才允许配置蓝图。
2. **蓝图闸门**：教师确认结构后，才允许生成；生成后结构不可被 AI 改。
3. **成卷闸门**：存在 blocker 时不允许正式导出；可导出带“草稿”水印的版本。

### 10.3 状态机

```text
idle
 → parsing → parse_review → parsed
 → blueprint → blueprint_ready
 → generating → reviewing → repairing → review_ready
 → assembling → ready
 → exporting → done
```

异常分支：`error`（可重试）、`aborted`（保留已完成）、`partial`（部分题目失败）。

- 状态转换由 store 的 action 控制，禁止在组件里散落布尔值。
- 每个异步任务带 `AbortController`；离开页面/点击中断时取消。
- 任何阶段失败都不清空已有数据。

| 指标 | 目标 | 测量方式 |

## 14. 风险与边界

| 风险 | 影响 | 应对 |
|---|---|---|
| AI 生成的题有知识错误 | 用户不信任 | 独立审题 + 出处 + 教师终审 + 明确免责声明 |
| 模型 JSON 不稳定 | 流程中断 | Zod + 提取 + 一次修复 + 原始输出可下载 |
| API 慢/贵 | 演示失败/成本高 | 按 section 批量、并发 2、超时、演示模式 |
| 真实大纲版权/隐私 | 合规风险 | 本地存储；示例大纲自写；不提交用户原始资料 |
| 教师不愿改变习惯 | 实用价值低 | 导出 Word/PDF 兼容现有流程；不强迫用系统排课 |
| 功能蔓延 | 交付失败 | P0 冻结；D5 后只修 bug |
| 演示现场网络差 | 现场翻车 | 演示模式 + 备份录屏 + 本地快照 |
| 名称/商标冲突 | 上线风险 | 提交前检索；备选名“卷衡/PaperLoom” |

### 明确边界

- 不保证题目达到正式考试命题质量；它是**辅助工具**，教师必须终审。
- 不处理学生个人数据；不提供自动评分。
- 不替代学校题库/教务系统；导出格式保持通用。
- 真实 AI 模式会把大纲内容发送给配置的模型服务商；README 必须提示。

## 16. 比赛版的“不做什么”清单

- 不做登录页；打开即用。
- 不做首页营销；首屏就是工作台。
- 不做多课程切换；一个项目一个课程。
- 不做题库；题目只属于当前试卷。
- 不做自动评分；只做命题和组卷。
- 不做复杂动画；动效只服务于状态理解。
- 不做移动端完整编辑；移动端保证可查看/可审阅，编辑以桌面为主。
- 不做“AI 全自动”；每个关键节点都要教师确认。
