# 07 · 用户验证与答辩

> 25% 的“实用价值”不是靠 PPT 讲出来的，是靠**真实用户、真实任务、真实反馈**撑起来的。
> 你不需要 100 个用户；**2–3 个真实教师/助教 + 一次完整试用**，比一堆假数据有力。

---

## 1. 先明确：你要验证什么

不是验证“用户觉得这个点子好不好”，而是验证：

1. 这个问题是否真的存在、多久发生一次、现在怎么解决。
2. 用户愿意把真实大纲交给你跑一遍吗？卡在哪。
3. 从打开到拿到可打印试卷，需要多久；是否需要你在旁边指导。
4. 用户敢不敢把这份卷子交给学生；最担心什么。
5. 哪个功能是“必须有”，哪个是“可有可无”。

---

## 2. 找谁

| 类型 | 人数 | 要求 | 渠道 |
|---|---:|---|---|
| 高校教师 | 1–2 | 近一学期亲自出过卷 | 任课老师、课程组、朋友介绍 |
| 助教/研究生 | 1 | 参与过出题/阅卷/排版 | 实验室、课程群 |
| 同学（备选） | 1 | 有课程设计/答辩出题经验 | 仅作为补充，文档写明身份 |

> 不要假装同学是“高校教师”。文档里如实写“课程助教/研究生”，可信度反而更高。

### 邀请话术

```text
老师您好，我在做一个“AI 辅助命题与组卷”的参赛项目，想占用您 20 分钟，
了解一下您平时出卷的流程和痛点。不会涉及学生隐私，也不要求您使用我的产品。
如果方便，您可以带一份脱敏的课程大纲，我现场跑一遍给您看。
```

## 3. 20 分钟访谈提纲

### 3.1 背景（3 分钟）

- 您这学期教什么课？几个班？大概多少人？
- 最近一次出卷是什么时候？什么类型（期中/期末/随堂）？
- 一般是自己出，还是课程组一起？

### 3.2 现有流程（7 分钟）

- 从决定出卷到最终打印，大概花多久？哪一步最耗时？
- 怎么保证覆盖了所有章节/重点？
- 怎么定难度和分值？会算吗，还是凭经验？
- 题目从哪里来：题库、旧题、教材、自己编？
- 答案和评分点怎么做？综合题怎么定步骤分？
- 排版一般用什么？Word？LaTeX？教务模板？
- 出完卷会自己再做一遍吗？有时间吗？

### 3.3 对 AI 的态度（5 分钟）

- 用过 ChatGPT/其他 AI 出题吗？为什么继续/为什么不用？
- 最担心 AI 出的题哪一点：知识错误、超纲、重复、答案不对、格式？
- 如果 AI 出题，您希望保留哪些控制权？
- 什么样的界面会让您“敢用”：看到出处？看到答案？看到审题意见？能单题改？
- 如果有一个工具能节省一半时间，您会用在期中/期末/随堂哪种？

### 3.4 收尾（5 分钟）

- 我能用您的一份脱敏大纲现场跑一遍吗？（演示模式/手动录入）
- 您愿意下周试用 20 分钟，给我一份反馈吗？
- 我可以在文档里引用您的原话吗？（匿名/署名，由您决定）

### 3.5 记录模板

```markdown
# 访谈 01

- 日期：
- 身份：高校教师 / 助教 / 研究生（不要美化）
- 课程：
- 出卷频率：
- 当前耗时：
- 最耗时步骤：
- 现有工具：
- 对 AI 的顾虑：
- 最想要的控制：
- 原话（经同意）：
- 是否愿意试用：
- 下一步：
```

## 4. 试用测试（30 分钟）

### 4.1 准备

- 用**演示模式**，避免网络/API 波动。
- 准备一份真实但脱敏的大纲；如果演示模式只支持内置示例，就让用户用示例，但明确说明。
- 不要在旁边指挥；只在用户卡住超过 2 分钟时给最小提示。
- 录屏（经同意）或记录关键时间点。

### 4.2 任务

```text
任务：请用这个工具，为《数据结构》出一份 100 分、120 分钟的期中试卷，
要求覆盖 6 章、难度 3:5:2，最后打开打印预览。
```

### 4.3 观察点

| 阶段 | 看什么 | 记录 |
|---|---|---|
| 打开 | 是否知道从哪开始 | 首次点击 |
| 大纲 | 是否理解“解析/确认” | 是否找按钮、是否读出处 |
| 蓝图 | 是否理解权重/分值/难度 | 是否算错、是否卡在总和 |
| 生成 | 是否知道 AI 在干嘛 | 是否等待焦虑、是否点中断 |
| 审校 | 是否看得懂风险/证据 | 是否敢通过、是否找到修复 |
| 成卷 | 是否能打印 | 是否找到答案卷/打印 |
| 快照 | 是否理解复现 | 是否尝试导出/导入 |

### 4.4 计时

- T0：打开页面。
- T1：完成大纲确认。
- T2：完成蓝图。
- T3：生成完成。
- T4：审校完成。
- T5：打印预览打开。
- 总时长；卡点次数；求助次数。

### 4.5 试用后问卷（5 点量表）

1. 这个工具帮我节省了时间。
2. 我能控制试卷结构，而不是被 AI 牵着走。
3. 审题意见让我更信任结果。
4. 界面清晰，我知道下一步做什么。
5. 我愿意在下次出卷时继续使用。
6. 我愿意把它推荐给同事。

开放问题：

- 最有用的一点是什么？
- 最想删掉/改掉的一点是什么？
- 如果只能保留一个功能，你选哪个？
- 你敢把这份卷子直接交给学生吗？为什么？

### 4.6 结果记录

```markdown
# 试用 01

- 用户身份：
- 使用模式：演示 / 真实
- 总时长：
- 各阶段耗时：
- 完成情况：独立完成 / 提示后完成 / 未完成
- 卡点：
- 问卷均分：
- 最有用：
- 最想改：
- 是否愿意继续使用：
- 原话（经同意）：
- 我们决定改什么（按优先级）：
```

> 不要为了好看改数据。用户说“还行”就写“还行”，不要写成“高度认可”。

## 5. 指标与写法

### 5.1 可以写的

- “3 位试用者中，2 位在 30 分钟内完成了从大纲到打印预览；1 位卡在蓝图权重合计。”
- “5 点量表均分 4.2（n=3），最低项是‘首次使用能独立完成’（3.7）。”
- “一位教师原话：‘审题证据比直接给我一堆题更有用。’（匿名，经同意）”
- “样本很小，结论是初步观察，不足以代表所有教师。”

### 5.2 不要写的

- “效率提升 80%”（没有对照实验）
- “100 位教师一致好评”（没有）
- “彻底解决出卷难题”（做不到）
- “AI 准确率 99%”（没有测量）
- 把同学写成“高校教师”

### 5.3 如果只有 1 位用户

写清楚：

> “n=1 的探索性试用，用于发现可用性问题，不代表统计结论。该用户完成了主线，但在蓝图页停留 6 分钟；我们据此把‘权重合计’提示提前到输入框下方。”

这比编造 10 条好评可信。

## 6. 答辩：10 个必问问题

### Q1：这不就是 ChatGPT 套壳吗？

**答：** 不是。ChatGPT 是“给主题→自由生成”；我们是“先编译结构，再填内容”。三个机制不同：

1. 蓝图和契约是确定性代码，AI 不能改结构；
2. 审题是另一个 Agent 独立作答，不是生成模型自查；
3. 结果有快照/哈希/回放，能复现和审查。

如果只是套壳，不需要分配算法、契约校验、审题证据和复现包。

### Q2：AI 出的题错了怎么办？

**答：** 三层防线：

1. 生成前：契约限定章节、知识点、题型、分值、难度、禁止项；
2. 生成后：独立审题 Agent 先做题再比对，问题必须有证据；
3. 最终：教师审校、通过、锁定；系统不自动把 AI 的题发给学生。

我们不承诺 100% 正确；我们承诺**可检查、可修复、可追溯**。这是辅助工具，不是替代教师。

### Q3：为什么需要多 Agent？一个模型不就行？

**答：** 因为“编”和“挑错”是冲突的目标。让同一个模型自查，它会倾向于证明自己写得对。审题 Agent 不看成生成理由，先独立作答，再比对，能发现更多问题。这是对抗式校验，不是把同一个调用拆成三个名字。

### Q4：怎么保证覆盖和难度？

**答：** 生成前用最大余数法把章节权重、难度比例分配到每个题目槽位；生成后计算 target/actual 偏差；偏差超过单题最大分值就 warning。教师能在覆盖矩阵里看到每一章的分值，而不是事后数。

### Q5：真实 AI 模式能逐字复现吗？

**答：** 不能，也不应该这样承诺。LLM 受模型版本、温度、服务端实现影响，重新生成不会逐字相同。我们复现的是**当时的完整产物和证据**：快照保存蓝图、题目、审题、Prompt 版本、模型参数、种子、哈希；回放不调用模型。确定性部分（分配、组卷、编号、总分、哈希）可以逐字复现。这个边界我们写在 README 和技术文档里。

### Q6：没有 API Key 怎么演示？

**答：** 内置演示模式：示例大纲、题库、规则审题、预置的歧义题，完整跑通“解析→生成→审题→修复→成卷”。界面明确标注“演示模式”，不假装是实时 AI。真实模式才调用模型。

### Q7：数据/隐私怎么处理？

**答：** 默认本地存储，无账号、无数据库、无分析 SDK。真实模式会把大纲/题目发送给用户配置的模型服务商；README 明确提示不要输入机密内容。API Key 只在服务端环境变量，前端拿不到。模型输出做 Markdown 清洗，禁止执行 HTML/JS。

### Q8：为什么不用数据库/Next.js？

**答：** 比赛版本的目标是 10 分钟复现、单进程、无运维。项目数据在浏览器，服务端无状态；Express + Vite middleware 足够，且请求路径透明，方便答辩。不是“不能做”，是当前阶段不值得增加复杂度。

### Q9：你的创新点到底是什么？

**答：** 一句话：**把“出题”从一次性 Prompt，变成可校验的编译流程。**

- 蓝图：结构先定；
- 契约：约束先定；
- 独立审题：证据先定；
- 快照：复现先定。

不是模型更强，而是**工作流更可控**。

### Q10：如果给你更多时间，下一步做什么？

**答：** 按优先级：

1. 真实课堂 pilot（一学期，收集 20+ 份试卷）；
2. 题库/旧题复用与去重；
3. 多课程模板与课程组协作；
4. DOCX/LaTeX 导出；
5. 题目难度校准（用学生作答数据）。

不会先做“更多 Agent”或“更炫的动画”。

## 7. 3 分钟电梯陈述

```text
高校教师出一套有依据的试卷，通常要 4–8 小时：对大纲、算分值、找题改题、
做答案、审题、排版。直接问 ChatGPT 很快，但结构不可控、答案难信、无法复现。

题衡把这件事变成一条编译流程：
先把大纲解析成知识点，再让教师定蓝图——总分、章节权重、难度、题型；
系统把蓝图编译成一份份“命题契约”，AI 只能在契约里写题；
另一个 Agent 不看创作理由，先独立做一遍，再比对答案，问题必须引用证据；
教师终审、锁定，最后确定性组卷、A4 打印，并把整张卷连同证据打包成可回放的快照。

我们不是让 AI 替代教师，而是让教师从重复劳动里出来，
把时间花在选题、育人、判断上。

这就是题衡：先定蓝图，再出好题。
```

## 8. 演示翻车预案

| 故障 | 现场动作 | 话术 |
|---|---|---|
| API 超时 | 切演示模式 | “真实接口延迟不稳定，我用同一版本的演示模式继续，流程完全一致。” |
| 页面白屏 | 刷新；仍不行则放录屏 | “我先放备份录屏，稍后可以看仓库里的复现包。” |
| 数据丢了 | 导入预先导出的快照 | “快照就是为这个场景设计的，导入即可回到终稿。” |
| 打印错位 | 换 Chrome/Edge；改边距 | “浏览器打印差异，我们准备了 PDF 备份。” |
| 评委追问数据 | 如实说样本量 | “n=3 的初步观察，不是统计结论；原始记录在 docs/validation。” |
| 时间不够 | 直接跳到审校/成卷 | “我跳过生成等待，直接看已经生成好的这一版。” |

**必备备份：**

- 完整演示录屏（MP4）。
- 终稿快照 `.papercompile.json`。
- 试卷/答案 PDF。
- 技术文档 PDF。
- 本地可运行仓库（不要只依赖线上）。

## 9. 诚信底线

- 不伪造用户身份、原话、数据、提交时间、AI 对话。
- 不把开源项目/模板包装成原创。
- 不承诺 AI 100% 正确。
- 不隐藏限制；主动说“不做什么”反而增加可信度。
- 评委可能要求现场复现；确保你能解释每一段核心代码和每一次提交。

> 比赛最重要的不是“看起来完美”，而是**真实、可复现、能讲清楚**。
