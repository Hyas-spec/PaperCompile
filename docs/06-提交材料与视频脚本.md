## 3. README 模板

> 不要直接复制占位符；没有实现的删掉，不要写“计划中”冒充已完成。

```markdown
# 题衡 PaperCompile

> 先定蓝图，再出好题。把教学大纲编译成一份可解释、可审查、可复现的试卷。

![首页](docs/assets/screenshot-home.png)
![审校台](docs/assets/screenshot-review.png)
![成卷](docs/assets/screenshot-paper.png)

## 问题

高校教师出一套有依据的试卷通常要 4–8 小时：对大纲、配分值、找题改题、做答案、审题、排版。
直接问 ChatGPT 很快，但结构不可控、答案难信、无法复现。

## 方案

大纲 → 知识点 → 命题蓝图 → 命题契约 → 3 个 AI 角色 + 1 个确定性编译器 → 教师终审 → 成卷。

- **Blueprint-first**：结构由教师定，AI 不自由发挥。
- **命题契约**：每道题生成前就有明确约束，生成后逐条校验。
- **独立审题**：审题 Agent 先独立作答，再比对答案，问题必须引用证据。
- **可回放**：每次成卷保存快照（Prompt 版本/模型/种子/哈希），回放不调用模型。

## 功能

- 大纲解析与知识点管理
- 蓝图配置、确定性分值分配、覆盖矩阵
- 多 Agent 出题/审题/定向修复
- 教师审校台（编辑/通过/锁定/重生成）
- A4 试卷 + 答案卷 + 打印/PDF
- 质量报告、快照、复现包

## 快速开始（10 分钟）

前置：Node.js 20+、npm。

```bash
git clone <repo-url>
cd papercompile
npm install
cp .env.example .env    # 可选；不配置也能用演示模式
npm run dev
```

打开 `http://localhost:5173`，点击“载入示例课程”，按“解析 → 蓝图 → 生成 → 审校 → 成卷”走一遍。

- **演示模式**：无需 Key，离线可用，内置《数据结构》示例与题库。
- **真实模式**：在 `.env` 配置 OpenAI 兼容接口后重启：

```bash
AI_BASE_URL=https://api.deepseek.com
AI_API_KEY=***
AI_MODEL=deepseek-chat
```

> Key 只在服务端使用，不会进入浏览器。真实模式会把大纲/题目发送给你配置的模型服务商，请勿输入机密内容。

## 测试与构建

```bash
npm run check      # typecheck + lint + test + build
npm run test:e2e   # Playwright 主线（演示模式）
npm run build
npm start
```

## 架构

浏览器（React + Zustand + localStorage） ⇄ 同源 Express（SSE / AI Provider） ⇄ OpenAI 兼容接口

- 确定性内核：蓝图分配、契约生成、组卷、哈希
- AI 层：大纲解析 / 命题 / 审题 / 修复，可降级到演示模式
- 数据：本地优先，无数据库；快照可导出/回放

详见 [技术文档](docs/tech-report.pdf) 与 [架构说明](docs/03-技术方案与架构.md)。

- 真实模式不承诺逐字复现；快照回放的是当时的完整产物。
- 不提供学生端、自动阅卷、题库。

# 10 分钟复现指南

## 0. 环境

- OS：Windows 10/11 / macOS / Linux
- Node.js：20 或 22（推荐 22 LTS；开发机 24 也可）

```bash
git clone <repo-url>

npm ci

| 问题 | 解决 |

| 端口被占用 | 改 `.env` 的 `PORT`，或关闭占用进程 |

| 演示模式没出现 | 检查 `.env` 是否设置了 `DEMO_MODE=1`；无 Key 时 auto 会进入 |

| 快照导入失败 | 确认是 `.papercompile.json`，版本一致；看错误提示 |

## 6. 预期结果

- 至少 1 条审题问题，可修复；

## 7. 演示视频脚本（7–8 分钟）

### 7.1 基本要求

- MP4，1920×1080，30fps，H.264。
- 5–8 分钟；至少 2 分钟“AI 协同过程复现”。
- 有字幕/旁白；不要只放 PPT。
- 不伪造操作；可以加速等待，但标注“2×”。
- 背景音乐可选，音量低；不要盖住旁白。

### 7.2 分镜

| 时间 | 画面 | 旁白/字幕 | 证据 |
|---|---|---|---|
| 0:00–0:20 | 空白 Word + 计时器 4:00:00，切到成卷 + 22:00 | “出一套有依据的试卷，过去要 4 小时；现在 22 分钟。差别不是写得快，是结构先被算清楚。” | 前后对比 |
| 0:20–0:40 | 教师访谈截图/原话（经同意） | “我们访谈了 3 位教师，最痛的不是写题，是对大纲、算分值、做答案。” | 访谈 |
| 0:40–1:10 | 打开应用，载入示例，展示大纲原文 | “这是《数据结构》的真实教学大纲。先解析，不生成。” | 产品 |
| 1:10–1:40 | 解析结果，展开 sourceQuote；删一个知识点 | “每条知识点必须指回原文；AI 只抽取，不发明。教师可以删改。” | 产品/防幻觉 |
| 1:40–2:20 | 蓝图页，改章节权重/难度，覆盖矩阵变化 | “结构由教师定：100 分怎么分到 6 章，系统实时算，偏差可见。” | 算法 |
| 2:20–2:50 | 生成，Agent 工作台流式状态 | “命题官按契约写；审题官不看创作理由，先独立做一遍。” | 多 Agent |
| 2:50–3:30 | 标红题，证据，修复 diff，复审 | “它指出答案与题干条件矛盾，只改这一道，其他不动。” | 审题/修复 |
| 3:30–4:00 | 审校台通过/锁定 | “教师始终是终审；锁定后 AI 不能覆盖。” | 控制权 |
| 4:00–4:30 | A4 预览、答案卷、打印 | “总分、题号、答案、评分点对齐；A4 直接打印。” | 闭环 |
| 4:30–4:50 | 快照/回放，哈希 | “同一份快照，随时还原现场，不调用模型。” | 复现 |
| 4:50–6:50 | **AI 协作实录**：输入 Prompt → AI 生成蓝图算法/修复 JSON → 跑测试 → commit | “这是真实开发过程：我们让 AI 实现分配算法，第一版平均分导致偏差；第二轮加入最大余数法和边界测试。” | 比赛硬要求 |
| 6:50–7:20 | commit 图、Prompt 日志、测试/Lighthouse | “40+ 次提交、5 条 Prompt 链、CI 绿灯。不是最后一天拼出来的。” | 过程 |
| 7:20–7:40 | 限制 + 未来 + 结尾 | “AI 不替代教师；它把教师从重复劳动里解放出来。题衡，先定蓝图，再出好题。” | 收束 |

### 7.3 2 分钟 AI 协作段（必须真实）

推荐录“蓝图分配算法”的修复，因为冲突清晰、容易看懂：

1. **0:00–0:20**：展示原始 Prompt（P04 片段）+ AI 首轮计划。
2. **0:20–0:50**：展示第一版结果：章节偏差 8 分，覆盖矩阵红色。
3. **0:50–1:20**：展示你的第二轮 Prompt：指出“平均分不满足权重”，要求最大余数 + 种子 + 边界测试。
4. **1:20–1:50**：AI 修改代码；终端跑测试，从失败到通过。
5. **1:50–2:10**：`git diff` + commit；展示 Prompt 日志对应条目。
6. **2:10–2:20**：一句复盘：“关键不是让 AI 写，而是我知道怎么判断它写错了。”

**录制要求：**

- 屏幕字体 ≥16px，能看清 Prompt/代码。
- 不要剪掉“失败”的那一段；失败与修复才是过程。
- 不要用 AI 生成一段“假对话”再录；评委会问细节。
- 如果不方便录 IDE，录聊天窗口 + 终端 + 浏览器结果，三段拼接。

### 7.4 录制流程

1. 先写逐字稿/分镜，不要即兴。
2. 用演示模式彩排 3 次，计时。
3. 清理桌面/通知/浏览器标签；关闭私人信息。
4. 分段录：产品演示、AI 协作、证据；最后剪。
5. 加字幕；关键数字用大字标注。
6. 导出 MP4 1080p；检查音量、清晰度、总时长。
7. 上传前在另一台设备播放一遍。
