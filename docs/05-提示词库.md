# 05 · 提示词库（可直接复制）

> 用法：**一次只复制一条**。大功能先让 AI 给计划，你确认后再写代码；完成后自己验收、跑检查、提交，再复制下一条。
> 每条 Prompt 都假设 AI 能读到仓库里的 `PROJECT.md`、`CURRENT_STATE.md` 和相关 docs。新会话第一条先发 P00 或“上下文重载”。

---

## 使用规则（先读）

1. **不要一次粘贴多条 Prompt。** AI 会顺手做一堆未验收的东西。
2. **不要跳过 P02/P04 直接做 AI。** 确定性地基不稳，后面全是补丁。
3. **AI 说“完成”不算完成。** 你必须自己点一遍、看 Console、跑 `npm run check`、试一个失败场景。
4. **不要让 AI 自动 push。** 本地提交可以；push 你自己来，避免把密钥/垃圾文件推上去。
5. **每条核心 Prompt 存日志。** 至少保存：Prompt 原文、AI 首轮建议、你的判断、修复过程、commit。
6. **提示词里的“验收标准”就是你的验收清单。** 不通过就不进入下一条。

## P04 · 蓝图配置与确定性分配

```text
【P04 · 蓝图配置与确定性分配】

先读 PROJECT.md、CURRENT_STATE.md、docs/02-项目方案-PRD.md 的第 7.3、9 节、docs/03-技术方案与架构.md 的第 6 节。

目标：
完成步骤 02：配置命题蓝图，做硬校验，生成确定性的题目契约和覆盖矩阵。此阶段不接 AI。

范围：
- 蓝图表单：考试名称、课程、时长、总分、难度比例（易/中/难）、章节权重、题型表格（题型/题量/每题分值/小计）、约束文本。
- 实时校验：
  - Σ(题量×每题分值) = 总分；否则显示差额并禁用生成。
  - 章节权重合计 = 100；难度合计 = 100；提供“自动归一”但必须用户确认。
  - 空章节/题量小于章节数给 warning，不静默改。
- 分配算法（纯函数，放 shared）：
  - 最大余数法把章节权重/难度比例换算成目标分值。
  - 槽位按分值降序；贪心选剩余目标最大的章节/难度。
  - 带种子的 PRNG 选知识点；优先未使用、importance 高；同章用尽允许重复并 warning。
  - 输出 QuestionContract[] + AllocationReport（target/actual/deviation/warnings）。
- 覆盖矩阵：章节 × 难度 × 题型的 target/actual 对比，偏差 ≤ 单题最大分值；红色标出问题。
- 契约预览：至少能看到每个槽位的章节、知识点、题型、分值、难度。
- 单测至少 8 个：正常 100 分、权重不整除、0 权重、单章、单题、难度极端、空章节、同 seed 一致。
- 所有计算用 useMemo/纯函数，禁止在 render 里重复分配。

不要做：
- 不接 AI；不做命题/审题/成卷页面。
- 不引入优化求解器；保持最大余数 + 贪心。
- 不要静默修改用户输入。
- 不要自动 commit/push。

工作方式：
1. 先给 10 行计划：算法步骤、数据流、测试用例、UI 组件。
2. 等我确认后实施。
3. 完成后运行 `npm run check`，贴测试结果。
4. 给我 4–5 条原子提交建议。
5. 更新 CURRENT_STATE.md。

验收标准：
- 示例《数据结构》100 分/10 题能生成 10 个契约，总分精确 100。
- 章节偏差 ≤ 单题最大分值；覆盖矩阵 target/actual 可见。
- 非法蓝图（总分/权重/难度不闭合）不能生成，错误定位到字段。
- 空章节有明确错误，不生成半套契约。
- 同 seed 两次分配结果完全一致。
- `npm run check` 通过。
```

## P06 · 命题 Agent 与演示题库

  - 命题步骤：开始生成、进度（N/M 部分）、题目卡逐步出现、单题失败可重试、全部完成进入审校。

  - 中断后保留已完成题目。
- 测试：
  - 契约校验、批量部分失败、单选唯一答案、评分点合计、重复题检测。
  - 演示模式 10 题全部生成；同一契约不重复取同题。

- 不做审题/修复（P07）；不做审校台（P08）。

- 不信任模型 selfCheck；必须服务端校验。
- 不要自动 commit/push。

1. 先给 10 行计划：批处理、schema、校验、演示题库结构、失败策略。
2. 等我确认后实施。

4. 给我 4–6 条原子提交建议。

## 通用辅助 Prompt

### A. Bug 修复

```text
【Bug 修复】

现象：
复现步骤：
期望：
实际：
错误日志/截图：
最近改动：
相关文件：

约束：
- 先不要改代码。先根据日志和代码定位根因，给最多 3 个可能原因，并说明如何验证。
- 确认根因后，给最小修复方案；不要重构无关模块。
- 修复必须带一个回归测试（先失败，再通过）。
- 不要自动 commit/push。

完成后给我：
1. 根因一句话；
2. 改了哪些文件/为什么；
3. 测试结果；
4. commit message；
5. 我手动验收的 3 个步骤。
```

### B. 纠偏 / 回滚

```text
【暂停，纠偏】

你现在的改动超出了本次范围：
- 本次只做：
- 你额外做了：
- 影响：

请：
1. 停止继续实现。
2. 列出未提交的改动。
3. 回滚与本次无关的改动（不要动我已经确认的部分）。
4. 用最小方案重新实现本次目标。
5. 重新运行检查。

如果你不确定哪些该保留，先停下来问我，不要猜。
```

### C. 拆分提交

```text
【拆分提交】

请查看当前 git diff，把它拆成最多 4 个原子提交：
- 每个提交只做一件事；
- 测试与对应功能放在一起；
- 不提交 .env/node_modules/dist/大文件；
- 提交信息用 conventional commits，body 写“为什么”和对应 Prompt ID；
- 不要自动 commit/push，先给我命令和每个提交包含的文件。

如果 diff 里有与本次任务无关的改动，先指出来，不要打包进去。
```

### D. 记录 Prompt 日志

```text
【更新 Prompt 日志】

请根据本次会话，帮我填写 docs/prompt-log/P{编号}.md：
- 目标；
- 完整 Prompt（原文）；
- AI 首轮建议摘要；
- 我发现的问题；
- 第二轮 Prompt/修复；
- 最终 diff / commit；
- 测试与验收；
- 复盘：下次怎么提问更好。

不要编造未发生的对话；没有的部分写“未记录”。
```

### E. 今日收工

```text
【今日收工】

请：
1. 运行 npm run check，贴结果。
2. 汇总今天完成的 3 件事、未完成的 1 件事、明天的第一件事。
3. 更新 CURRENT_STATE.md。
4. 检查 git status，列出未提交文件和建议的提交拆分。
5. 提醒我保存今天的截图/录屏证据。

不要自动 commit/push。
```
